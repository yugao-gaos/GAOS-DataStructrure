Working with Enums in DataStructure

DataStructure supports storing and manipulating enum values, providing a type-safe way to work with categorical data in your game. Enums offer a clean, self-documenting approach to representing choices, states, or options in your game data.

Registering Enum Types

Before an enum can be used in DataStructure, it must be registered with the system. There are two ways to register enum types:

1. Using the DataStructureEnum Attribute

The simplest way to register an enum is to mark it with the [DataStructureEnum] attribute: 

using GAOS.DataStructure;
using System;

// Regular enum example
[DataStructureEnum]
public enum ItemRarity
{
    Common,
    Uncommon,
    Rare,
    Epic,
    Legendary
}

// Flags enum example
[Flags]
[DataStructureEnum]
public enum StatusEffects
{
    None = 0,
    Poisoned = 1 << 0,    // 1
    Burning = 1 << 1,     // 2
    Frozen = 1 << 2,      // 4
    Stunned = 1 << 3,     // 8
    Bleeding = 1 << 4,    // 16
}

Enums marked with this attribute are automatically discovered and registered during initialization, requiring no additional code.

2. Manual Registration

You can also register enum types manually using the EnumRegistry class: 

// Register in a static constructor
static YourClass()
{
    EnumRegistry.RegisterEnum<WeaponType>();
}

// Or register at runtime
void InitializeData()
{
    EnumRegistry.RegisterEnum<DamageType>();
    // Continue with other initialization...
}

Manual registration is useful when you want to register enums from third-party code or when you want more control over when registration occurs.

Using Enums in DataStructure

Once registered, enums can be used like any other data type in your DataStructure containers: 

// Create a container with an enum value
var container = new DataContainer();
container.SetValue<ItemRarity>("itemRarity", ItemRarity.Rare);

// Get an enum value
ItemRarity rarity = container.GetValue<ItemRarity>("itemRarity");
if (rarity == ItemRarity.Legendary)
{
    // Handle legendary item logic
}

// Use in nested structures
container.SetValue<StatusEffects>("player.status.effects", StatusEffects.Poisoned | StatusEffects.Burning);

// Check for specific flags
StatusEffects effects = container.GetValue<StatusEffects>("player.status.effects");
if ((effects & StatusEffects.Poisoned) != 0)
{
    // Handle poisoned status
}

Flags Enum Support

DataStructure has special support for enums marked with the [Flags] attribute:

  • The editor UI displays a multi-select interface for flags enums
  • Multiple values can be combined using bitwise operations
  • Individual flags can be checked with bitwise operations

This makes flags enums ideal for representing combinations of options or states, such as:

  • Status effects on a character
  • Permission settings
  • Configuration options
  • Collision layers

Best Practices

Naming and Organization

  • Use singular names for regular enums (ItemType, WeaponClass)
  • Use plural names for flags enums (StatusEffects, CharacterAttributes)
  • Group related enums in appropriate namespaces

Value Assignment

  • For flags enums, always use powers of two (1, 2, 4, 8, etc.) or bit shift operations (1 << 0, 1 << 1, etc.)
  • Include a None = 0 value in flags enums
  • Consider including an "Unknown" or "Default" value in regular enums

Performance Considerations

  • Enum registration is optimized to use reflection only during initialization
  • Runtime operations use cached type information for performance
  • Enum values are serialized as integers for reliability

Technical Details

DataStructure uses several components to support enums:

  • EnumRegistry: Central registry that maintains type information for all registered enums
  • DataStructureEnumAttribute: Attribute for automatic registration
  • EnumEditor: Custom editor UI for displaying and editing enum values

Serialization is handled automatically, with enum values stored as integers for maximum compatibility across different platforms and versions.
